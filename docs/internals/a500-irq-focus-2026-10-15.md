# A500 masked request and instruction IRQ polls, 15 October 2026

## Result

Physical One ROM measurements identify and close three interacting issues:
Copperline sampled INTREQR one trailing bus clock too late, qualified ordinary
68000 polls against a deadline already calibrated for STOP, and did not retain
the early operand poll for memory TST. No program identity checks or global
STOP-latency changes are involved.

## Physical setup and suite

PAL A500, 512 KB chip + 512 KB slow RAM, ECS Agnus (`VPOSR a000`), OCS Denise
(`DENISEID ffff`), stock 68000. One ROM Fire-40-A provides the ROM, SEL_C reset,
and RBCP USB result transport. Captures include source fingerprints, descriptors,
checksums and executable provenance. Results were collected twice without
physical probe wiring. The repeated focused run agrees on all compared fields;
one unrelated VERTB bit in a masked INTREQR word differs, so the two entire
focused packets are not claimed byte-identical.

Kind 43 has four entry phases, 64 delays for masked COPER readback and each of
NOP, MOVEQ, EXG, TST.W Dn, TST.W (An), TST.W d16(An), TST.L (An), plus 41 safe
delays for STOP. The launch beam is recorded before the variable delay. Running
instruction tails contain straight-line NOPs, avoiding a TST polling loop that
would confound the target instruction's poll. The IRQ handler records saved PC,
beam and whether the following marker executed.

STOP delays above 40 are omitted: the first IRQ could execute before STOP,
then a later frame's IRQ could overwrite the first measurement. Exploratory
v2 had these unsafe rows and is superseded. Immutable v2/v3 manifests contain
the label `BLIT` for mask `$0010`; this is a naming error only: `$0010` is
COPER, while BLIT is `$0040`. The archived assembly, actual mask and comparisons
are consistent. Current builder labels correct it. Preserve archived inputs.

## Timing explanation and changes

Masked COPER readback changed from first-observed delay 45/44/44/43 to the
A500/WinUAE values 46/45/45/44. Bracketing beam reads were already identical.
`custom_read` previously read the live register after the CPU transfer and its
trailing CCK had both elapsed. It now captures INTREQR at the granted transfer
before that tail. This fixes all four threshold mismatches without changing
Paula's raw latch or adding a register-specific propagation delay. Byte and
longword tests cover lane selection and the INTREQR word's own transfer slot;
the short 020+ return path remains unchanged.

Running NOP/MOVEQ/EXG/TST-register recognition was generally two CCK late.
The six-CCK setting is an instruction-boundary eligibility deadline calibrated
from the combined STOP path, not a direct Paula-pin measurement. Ordinary
stock-68000 qualified samples now use deadline minus two CCK, accounting for
the final transfer before the decision. Memory TST uses a separate unqualified
operand candidate, deadline minus four CCK, retained through the final prefetch.
TST.L reads its two words separately and holds the low-word sample. Faults
return before holding the poll or updating CCR. Other CPU models and accelerated
bus ratios retain previous poll qualification. STOP's deadline/grid is unchanged.

A diagnostic global setting of four CCK made the running instructions match
but broke 252 of 256 exploratory STOP rows. That diagnostic is not the fix.
Separating poll qualification instead also makes the older divider packet
byte-identical to hardware, including its waiting-loop TST observations.

## Remaining verification plan

These results establish the measured A500 cases, not universal IRQ accuracy.

1. Repeat memory TST with chip-RAM code and operands while bitplane, Copper,
   sprite, refresh and blitter DMA independently delay operand and prefetch
   accesses. Sweep source edge in one-CCK steps, record first IRQ only, saved
   PC, marker and handler beam. In particular force contention between operand
   poll and final prefetch, so the explicit early hold is distinguishable from
   an accidentally equivalent no-contention final poll.
2. Add other instruction classes with distinct polls: memory MOVE, RMW,
   read/write multiword operations, branches and exception return. Use short
   straight-line tails and finite source events. Record IRQ count so a later
   frame cannot silently replace the intended first event.
3. Independently sweep CPU versus Copper INTREQ set/clear, masked/unmasked
   INTENA, already-pending requests and two simultaneous priority levels.
   Include CIA PORTS/EXTER and native BLIT. This tests source qualification
   and deassertion instead of extrapolating from COPER assertion alone.
4. Add low-word/high-word fault and address-error controls around newly
   explicit word transfers; check save/resume and exact rollback at poll holds
   and recognition deadlines. Existing unit coverage is not every bus-fault
   ordering or save-state phase combination.
5. If software-visible cases cannot distinguish a pin delay from a CPU poll
   qualifier, use the Rigol digital channels on IPL[2:0], AS, DTACK and clock
   with a common ground and suitable loading. One ROM can run matched marker
   kernels. External traces are needed for a direct pin-propagation claim;
   they were not needed to close these end-to-end observations.
6. Run controlled before/after host-performance benchmarks before claiming
   unchanged emulation speed. General AGA/accelerated CPU accuracy needs its
   own hardware evidence. Remaining line BZERO work in the older report is
   separate from these IRQ corrections.
