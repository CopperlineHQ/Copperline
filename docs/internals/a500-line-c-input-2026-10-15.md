Copperline and WinUAE each disagree with hardware on 40/344 BZERO
observations, with zero launch/end-beam, busy or memory differences.
The effect requires USEB clear, USEC set and two pixels. For those controls,
first C=0 clears BZERO, first C=ffff keeps it set; changing only the second
C word does not reproduce the inhibition, nor do BLTCDAT-only seeds.
Uniform first/second C=5555 inhibits the clear whereas aaaa does not.
No individual one-hot first-C bit inhibits the clear. Thus the data
dependency is in the first fetched C word and involves multiple bits;
the one-hot-only result does not identify a single controlling bit.

Next kind40 adds one-cold words and LF=c0 A-shift tomography at BSH4,
with independent DMA and one-pixel controls. This tests the effective
B-word bit incidence rather than guessing from the B-only OR flag.

For Cfirst=0 and LF=cc, both A values keep BZERO set at the earliest
read-end timestamp 18 CCK after the recorded launch beam, then show it
clear at read-end timestamp20 and all later samples; one-pixel controls
remain set. These are software observation timestamps, not a claim that
the internal flag changes at exactly20 CCK. The DMACONR read precedes its
beam timestamp. Phase kernels have launch positions4242/4243, so phase
and launch alignment must remain separate when interpreting the boundary.

For Cfirst=ffff, A=8000, two pixels, phase 1/delay 2 reads clear at endpoint23
CCK, but later trials read set. Cold-bit14 with A8000 reads clear at most
late positions, set at delays15, then clear again at delay16. These are
separate blits; this is not evidence that a single blit's flag actually
reasserted. It disproves using this sweep as a simple monotonic transition
or fixed C-bit mask without additional controls. An exact repeat is running.

## Next-step decision tree after the within-blit control

1. If post-busy sequence reads change within one blit, investigate readout
   bus influence or non-latched line-mode status. Repeat from slow RAM
   with the same opcodes, separating One ROM instruction serving from
   chipset effects; preserve exact per-mode cycle/beam provenance.
2. If each sequence is stable but independently launched trials differ,
   prime all normal-mode A/B/C holds before every trial, then compare
   forward/reversed/randomized preset order and controlled repeats.
   Kind34 only primed B and does not rule out other retained state.
3. Run a Copper-launched blit while the CPU is stopped, waking by a
   separately measured IRQ to read BZERO. Compare an equal-timeline
   active-CPU observer to isolate CPU-bus activity during the blit.
4. Only after those controls, collect held-out C combinations and full
   minterm closures at BSH4/6/8. A state-based datapath/visibility rule
   must predict both final flags and the early read matrix, and must
   preserve timing, memory and the already-matched normal/fill/IRQ sets.
5. Do not use a per-BSH mask lookup or optimize against non-repeatable
   rows. Extend the earlier wrap correction only when new capture sets
   have no regressions; rerun optimized core tests, goldens and a
   controlled performance workload if core code changes.

Each pattern repeats identically in all eight repeats for each A value.
The two modes differ in CPU activity between launch and sampling: one
performs the presample beam read/store directly, the other polls DMACONR
until BBUSY clears first. This supports an observer/history/CPU-bus effect
while the blit runs; it does not identify its internal latch mechanism or
prove the poll itself is the cause. They are separate blits, not a poll
inserted into an already measured blit.

Prioritize CPU-quiet Copper/STOP launch, controlled equal-cycle bus traffic
and full A/B/C priming, then ROM-versus-slow-RAM execution. A fixed mask
fit would miss this mode dependence and the kind41 run-to-run variation.
No new Copperline core correction is accepted from this batch. The
already-committed wrap fix is independently strengthened by the BSH0
controls; its remaining 58 rows include behavior outside the corrected path.
